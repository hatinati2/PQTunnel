# راهنمای آزمایشی انتقال پورت و خروجی انتخابی PQTunnel

**این قابلیت هنوز آزمایشی است. از اسکریپت‌های شبکه روی سرور اصلی یا میزبان دارای UFW، قوانین فایروال موجود، یا تونل‌های دیگر استفاده نکنید.** هیچ‌یک از تست‌های CI جایگزین آزمایش انتهابه‌انتها با دو میزبان جداگانه نیست.

## دو کاربرد مستقل

1. **Port forward ورودی روی ایران:** اتصال به `Iran-IP:LOCAL_PORT` با nftables به IP/پورت مشخص‌شده سمت آلمان DNAT می‌شود و برای برگشت، مبدأ به IP تونل ایران تبدیل می‌شود. مقصد باید IP literal باشد که در سمت آلمان local یا از راه forwarding قابل دسترسی است.
2. **خروجی انتخابی از ایران:** اتصال‌های محلی به TCP/UDP destination portهای مشخص‌شده با connection mark و policy routing به رابط TUN فرستاده می‌شوند. مسیر default جدول اصلی دست‌نخورده می‌ماند.

مثال تنظیمات:

```bash
PQTUNNEL_TUN_IF="pqtun0"
PQTUNNEL_TUN_IPV4="10.66.0.2"
PQTUNNEL_TUN_IPV6="fd66::2"
PQTUNNEL_WAN_IF="eth0"
PQTUNNEL_ENDPOINT="vpn.example.net"
PQTUNNEL_ENDPOINT_PORT="8443"
PQTUNNEL_EGRESS_TCP_PORTS="443,8443"
PQTUNNEL_EGRESS_UDP_PORTS="53"
PQTUNNEL_FORWARD_TCP="8443=203.0.113.10:443,2222=203.0.113.10:22"
PQTUNNEL_FORWARD_UDP="5353=203.0.113.10:53"
PQTUNNEL_PORT_POLICY="tcp:443,22;udp:53"
```

مقادیر `203.0.113.10` فقط نمونهٔ مستندسازی‌اند و باید با IP واقعی سمت مقصد جایگزین شوند. برای هدف IPv6 از `LOCAL_PORT=[IPv6]:REMOTE_PORT` استفاده کنید و `PQTUNNEL_TUN_IPV6` را خالی نگذارید. برای IPv6 خروجی انتخابی، هر دو سرور و میزبان مقصد باید IPv6 forwarding/routing واقعی داشته باشند؛ NAT66 فقط وقتی مفید است که آدرس‌دهی و upstream IPv6 سرور آلمان درست باشد.

## تطبیق allowlist پروتکل

فرمت `--port-policy` یا `PQTUNNEL_PORT_POLICY` چنین است:

`tcp:443,22;udp:53;icmp6`

همین allowlist را سمت `pqtunnel-client` در ایران و `pqtunneld` در آلمان تنظیم کنید. پورت‌های این فهرست، **پورت مقصد داخل تونل** هستند، نه لزوماً پورت عمومی ورودی ایران. مثلاً نگاشت `8443=203.0.113.10:443` به `tcp:443` نیاز دارد. اگر policy فعال باشد، بسته‌های IP fragment شده و پروتکل‌های غیرمجاز drop می‌شوند. برای PMTU/ICMP، سیاست ICMP را آگاهانه انتخاب کنید؛ صرفاً افزودن ICMP به allowlist به معنای ایجاد route برای آن در nftables نیست.

## اتصال به endpoint و DNS

`PQTUNNEL_ENDPOINT` نام دامنه یا IP سرور شنونده است. اسکریپت، آدرس‌های DNS فعلی را برای استثنای اتصال TLS ثبت می‌کند؛ پس از تغییر DNS باید پس از بررسی و rollback، قوانین را دوباره اعمال کنید. اگر UDP/53 نیز بین پورت‌های انتخابی است، درخواست‌های DNS bootstrap می‌توانند به تونل وابسته شوند. برای جلوگیری از loop، ترجیحاً `pqtunnel-client --server` را با IP ثابت اجرا و `--server-name` را روی نام داخل SAN گواهی بگذارید، یا DNS bootstrap را آگاهانه از policy تونل مستثنا کنید.

## اسکریپت‌ها

- `scripts/selective-ports-network.sh` فقط روی میزبان ایران/Dialer است. `validate` قواعد را بدون اعمال آن‌ها بررسی می‌کند؛ `apply --confirm-dedicated-host` مسیرهای policy، NAT/DNAT و forwarding را تغییر می‌دهد. `rollback` فقط تغییرات ثبت‌شدهٔ خودش را حذف می‌کند و نیازمند توقف کلاینت است.
- `scripts/gateway-network.sh` فقط روی میزبان آلمان/Listener است و NAT/forwarding خروجی dual-stack را برای subnet تونل آماده می‌کند. این اسکریپت از chain فوروارد با policy DROP استفاده می‌کند و برای میزبان اختصاصی آزمایشی است.
- هر دو اسکریپت در صورت تشخیص UFW فعال یا chain forwarding از اجرای خودداری می‌کنند. اسکریپت ایران هنگام تعریف port-forward علاوه بر آن، اگر IPv4 یا IPv6 forwarding از قبل فعال باشد نیز متوقف می‌شود؛ زنجیرهٔ DROP آن می‌تواند روی سایر ترافیک‌های عبوری اثر بگذارد. آن‌ها برای ادغام با فایروال موجود یا میزبان production آماده نیستند.
- اسکریپت‌های شبکه مسیر default جدول اصلی را تعویض نمی‌کنند، اما همچنان تغییر firewall/route هستند و ممکن است اتصال یا forwarding را مختل کنند. ابتدا در VM آزمایشی اجرا کنید و کنسول خارج از باند نگه دارید.

## پروفایل نمونه برای هر دو کاربرد

این مثال دو سرور را در حالت ایران=Dialer و آلمان=Listener فرض می‌کند. در ایران، بسته‌هایی که وارد TUN می‌شوند بعد از SNAT مبدأ `10.66.0.2` دارند؛ به همین دلیل allowlist مبدأ باید این آدرس را بپذیرد. در Listener آلمان، `PQTUNNEL_PEER_PREFIXES=10.66.0.2/32` و `PQTUNNEL_LOCAL_PREFIXES=0.0.0.0/0,::/0` فقط همراه با `PQTUNNEL_PORT_POLICY` محدودشده استفاده شود؛ باز گذاشتن مقصدها بدون محدودیت پورت، یک سیاست گسترده است.

- کلاینت ایران: `--local-prefixes 10.66.0.2/32 --remote-prefixes 0.0.0.0/0,::/0`
- Listener آلمان: `PQTUNNEL_PEER_PREFIXES=10.66.0.2/32`, `PQTUNNEL_LOCAL_PREFIXES=0.0.0.0/0,::/0`, `PQTUNNEL_PEER_NAME=iran`, `PQTUNNEL_MAX_CLIENTS=1`
- هر دو طرف: `PQTUNNEL_PORT_POLICY=tcp:443,22;udp:53` (فقط نمونه؛ دقیقاً با پورت‌های مقصدی که لازم داری تنظیم کن).
- نمونهٔ انتقال ورودی روی ایران: `PQTUNNEL_FORWARD_TCP=8443=GERMANY_SERVICE_IP:443`. جایگزین `GERMANY_SERVICE_IP` باید IP واقعی سرویس روی آلمان یا شبکهٔ پشت آن باشد؛ مقدارهای TEST-NET در فایل مثال را استفاده نکن.
- نمونهٔ خروجی انتخابی روی ایران: `PQTUNNEL_EGRESS_TCP_PORTS=443` و/یا `PQTUNNEL_EGRESS_UDP_PORTS=53`.

## محدودیت‌های فعلی

- این مرحله هر دو سیاست را مدل می‌کند: انتقال پورت ورودی ایران→آلمان (DNAT/SNAT) و خروجی انتخابی از ایران براساس پورت مقصد. این‌ها دو مسیر مستقل‌اند و لازم نیست هر دو فعال باشند.
- برای اطمینان از بازگشت پاسخ در port-forward، اسکریپت SNAT مبدأ را به IP تونل ایران تبدیل می‌کند؛ سرویس مقصد در آلمان معمولاً IP اصلی کاربر اینترنتی را نخواهد دید. حفظ IP اصلی به پروکسی لایهٔ ۴ یا طراحی جداگانه نیاز دارد.
- بسته‌های IP fragment شده در حالت port-policy رد می‌شوند، چون پورت لایهٔ انتقال برای همهٔ fragmentها قابل مشاهده نیست. این می‌تواند بر ترافیک خاص/PMTU اثر بگذارد و باید در تست‌ها بررسی شود.
- UDP از دید شبکهٔ IP عبور داده می‌شود؛ تضمین دوام UDP application-level یا حفظ تمامی رفتارهای NAT مختلف وجود ندارد.
- `gateway-network.sh` زنجیرهٔ `forward` با سیاست DROP می‌سازد و فقط برای میزبان آزمایشی اختصاصی است. **آن را روی سرور اصلی آلمان که ترافیک/فورواردینگ فعال دارد اجرا نکن.** برای سرور موجود باید سیاست فایروال جاری (مثلاً UFW/nftables) جداگانه و به‌صورت افزایشی بررسی و یکپارچه شود.
- `nftables` در این محیط توسعه نصب نبود؛ اسکریپت‌ها با `bash -n` بررسی شده‌اند، اما بررسی واقعی `nft -c` و اجرای شبکه روی میزبان واقعی هنوز انجام نشده است.
- CI فقط build، unit tests و checks موجود را اجرا می‌کند؛ هنوز آزمون واقعی دو سرور، هر چهار ترکیب Ubuntu 24.04/26.04، TLS negotiated group، قطع‌و‌وصل، packet fragmentation، و IPv4/IPv6 egress/forwarding انجام نشده است.
